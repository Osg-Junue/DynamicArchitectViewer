# プロダクトコンセプトと設計目標 (Vision & Goals)

## 1. 背景と解決する課題

既存の作図ツール（Draw.io、PowerPoint、Figma、Mermaid等）で作成されたインフラ構成図や画面遷移図には、以下の構造的な課題が存在します。

1. **「時間軸（シーケンス）」と「状態変化」が表現できない**
   - 1枚の静的な図の中に「通常時のリクエスト経路」「キャッシュヒット時」「DB障害時のフェイルオーバー経路」をすべて描き込むと、矢印と番号が錯綜し可読性が破綻します。
   - 結果として「構成図」と「シーケンス図」を別々に作り、読み手が頭の中で両者を突き合わせる負担が発生します。
2. **画面遷移とバックエンド通信の分断**
   - フロントエンドの画面遷移図（ログイン画面 → カタログ画面 → 決済モーダル → 完了画面）と、その裏で呼ばれるAPI・外部決済GWの通信フローが別資料に分断されがちです。
3. **閲覧環境の制約と共有コスト**
   - 専用アプリや特定SaaSアカウントがないと閲覧・再生できないツールは、顧客提出資料や閉域網・オフライン環境での共有に適しません。
4. **手動レイアウト調整のメンテナンス負荷**
   - GUI作図ツールや手動座標指定では、ノードを追加・削除するたびに手作業での位置調整が発生し、Git差分も肥大化します。

---

## 2. コアコンセプト

DynamicArchitectViewer は、上記4つの課題を以下のアプローチで解決します。

### ① 構成図 × ステップ再生（Time-Stepped Architecture & Screen Flow）

1つのベース構成図（ノード・グループ・エッジ）に対して、時系列の **`step`（ステップ）** を定義します。
ステップを進めるごとに、以下の要素が動的に切り替わります。

- **フォーカス強調 (`focus`)**: そのステップに関係するノード・経路のみをハイライトし、無関係な要素を減光（Dimming）
- **パケット移動アニメーション (`animate`)**: 接続線上を移動するデータパケットとラベル（例: `POST /orders`, `INSERT`, `Redirect /catalog`）の連続再生。`icon` を指定すると、トークンやファイルなど運ぶものをアイコンで示せる
- **状態オーバーライド (`state`)**: ステップの進行に沿って累積する障害表示（`color: red`, `badge: "DOWN"`）、スタンバイ昇格、非表示だったフェイルオーバー経路やモーダル画面の出現（`visible: true`）

### ② コード記述のみ × 100% 自動レイアウト（Code-Only & Auto-Layout）

- **コンパクトな独自DSL (`dav 1`)**: 手動座標指定を一切排除し、構造（`group` / `node` / エッジ）と時系列シナリオ（`step`）のみを宣言的に記述します。
- **AIエージェント & 人間双方に最適**: トポロジとグループ階層から決定論的に自動レイアウトされるため、AIエージェント（Antigravity / Claude Code / Copilot等）も人間も座標計算を意識せずコードだけで完結できます。
- **超軽量 Vanilla TypeScript 実装**: React等の重いUIフレームワークを排除した純粋なDOM/SVG実装により、VS Code 拡張機能としても単一HTMLとしても高速・省メモリに動作します。

### ③ 完全自己完結型の「1ペラHTML（Single-file HTML）」出力と再編集

- エディタから出力される成果物は、CSS・軽量再生ランタイムJS・内蔵SVGアイコン・図データをすべてインライン化した**単一の `.html` ファイル**です。
- 外部CDNや通信を一切行わないため、ローカルの `file://` 直開き、メール添付、社内ポータル、オフライン環境など、ブラウザさえあればどの環境でも即座に動的再生が可能です。
- さらに、出力された `.html` ファイル内部に元のDSLソースを埋め込んでいるため、**配布後のHTMLファイルをそのまま拡張機能に読み込ませてDSLを再抽出（Round-trip Re-import）**できます。
