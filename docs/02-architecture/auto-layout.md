# 自動レイアウトのルール

`.dav` には座標を書きません。ノードとグループの位置とサイズは `computeLayout(doc)`（[`apps/vscode/src/layout/index.ts`](../../apps/vscode/src/layout/index.ts)）がすべて決めます。この文書は、その配置ルールと、変更時に守る条件をまとめたものです。

線の経路（ノードを避ける曲線、並行する線のずらし）は `layout` ではなく `scene/resolve.ts` と `scene/geometry.ts` が決めます。

---

## 1. 入力と出力

| 項目 | ルール |
| :--- | :--- |
| 配置に使う情報 | `node` と `group` の宣言と階層、エッジ（ラベル幅と自己ループ数を含む） |
| 配置に使わない情報 | `step`、`animate`、`focus`、`state`。ステップが変わってもノードは動かない。`animate` だけで結んだノードは、接続がないものとして配置される |
| `visible: false` の要素 | 表示されるノードと同じように場所を取る。途中のステップで表示しても配置は変わらない |
| 出力 | ノードとグループごとの矩形（`Layout`）。JSON にできるプレーンなオブジェクト |
| 出力 HTML | 書き出し時に計算した `Layout` を埋め込む。後でルールを変えても、書き出し済みのファイルの配置は変わらない |

---

## 2. 処理の流れ

1. エッジから各ノードの列（ランク）を決める
2. 全体で共有する列の X 座標を決める
3. グループ階層に沿って、上から順に Y 座標を決める（初回配置）
4. 上下の順序を入れ替えて再配置を繰り返し、改善した結果だけを採用する（順序の改善）

---

## 3. 列（左から右）

- ノードの列は最長経路で決める。エッジのないノードは 0 列目に置く
- 循環は、宣言順に深さ優先探索したときの後退エッジを無視して解消する。そのため `a --> b` と `b --> a` では、先に宣言された `a` が左になる
- 自己ループは列の計算に使わない
- 列の X 座標は図全体で共有する。別のグループのノードでも、同じ列なら X 座標が揃う
- 列の間隔は `max(36, ラベルの必要幅 - 132) + グループの余白` で決める

| 要素 | 値 |
| :--- | :--- |
| ラベルの必要幅 | 隣り合う列を結ぶエッジのラベルのうち最大のもの。`min(180, ラベルの推定幅) + 32`。ラベルはノードの幅の下も使えるため、ノード幅 176 と駅の幅 44 の差である 132 を引く |
| グループの余白 | `グループの最大の深さ × 32` |
| 図の左端と上端 | `40 + グループの最大の深さ × 16` |

---

## 4. 行（上から下）

### 4.1 ブロックの積み方

グループ（またはトップレベル）ごとに、次の 2 種類のブロックを配置します。

- その階層に直接属するノードを列ごとにまとめたブロック
- 子グループ（またいでいる列の範囲を持つ）

ブロックは列ごとの「現在の下端」を使って置きます。

- 列の範囲が重ならないブロックは、同じ高さに横並びになる
- 列の範囲が重なるブロックは、下に積まれる（ブロックの間隔は 28）

初回配置のブロックの順序は、左端の列が小さい順で、同じ列なら列のブロック、子グループの順です。列のブロックと子グループの中は宣言順です。

### 4.2 ノードの並び

- ノードのサイズはアイコンによらず 176 × 118。行の間隔は 14
- 駅の中心は常にノード上端から 50 の位置にある。同じ Y 座標のノード同士を結ぶ線は水平になる
- 初回配置では、列の中のノードを配置済みの前段ノードの Y 座標の平均順に並べる。前段がないノードは後ろに置き、同じ値なら宣言順にする

### 4.3 自己ループの余白

- 自己ループを持つノードは、上に `30 + (ループ数 - 1) × 18` の余白が必要になる
- 同じ階層に直接属するノードのうち最大の余白を、その階層の全ノードの行に適用する。行が揃い、線が水平のまま保たれる

### 4.4 グループの枠

- グループは、直下のノード（自己ループの余白を含む）と子グループを包む矩形になる
- 周囲の余白は 16、上にグループ名の領域 18 を加える
- ノードを持たないグループは、0 列目に 160 × 40 の領域を確保する

---

## 5. 順序の改善

初回配置を基準として、上下の順序を変えた配置を繰り返し試します。

| 項目 | ルール |
| :--- | :--- |
| 繰り返し | 最大 16 回。改善しない回が 4 回続くと終了する |
| 列の中の順序 | 奇数回目は左の列のつながり先、偶数回目は右の列のつながり先の Y 座標の平均で並べる。つながり先がなければ前回の位置を保つ。同じ値なら前回の位置、宣言順の順で決める |
| ブロックの順序 | ブロックの外につながるノードの Y 座標の平均で並べる。外とのつながりがなければ、自身のノードの平均を使う。ノードを持たないグループは最後に置く |
| 採用の条件 | 交差数が減った場合、または交差数が同じで線の縦方向の長さの合計が短くなった場合 |
| 実行しない条件 | 自己ループを除くエッジが 0 本、または 500 本を超える場合（編集のたびに実行され、交差の計算量がエッジ数の 2 乗になるため） |

評価の定義は次のとおりです。

- 交差数は、エッジを駅の中心同士を結ぶ直線とみなして数える（`countCrossings`）。同じ駅を共有するエッジの組は数えない
- 実際に描かれる線は曲線でノードを避けるため、直線での交差数と描画上の交差数は一致しないことがある
- 線がほかのグループの領域を横切ることは評価していない

---

## 6. 書き手が配置に影響を与える方法

配置を直接指定する構文はありません。結果に影響するのは次の要素です。

| 変更 | 影響 |
| :--- | :--- |
| エッジの追加・削除・向きの変更 | 列が変わる |
| グループの構成 | ブロックの単位が変わる。同じグループのノードはまとまって配置される |
| 宣言の順序 | 同点の場合の順序と、循環のどのエッジを後退エッジとみなすかが変わる |
| エッジのラベルの長さ | 列の間隔が変わる |
| 自己ループ | その階層の行の間隔が変わる |

---

## 7. 変更時に守る条件

| 条件 | 確認するテスト（`layout/__tests__/layout.test.ts`、`scene/__tests__/scene.test.ts`） |
| :--- | :--- |
| 同じ入力からは常に同じ配置になる。乱数や順序が保証されない処理を使わない | `is deterministic` |
| ノード同士が重ならない。グループの中に無関係なノードが入らない | `auto layout never overlaps nodes or puts foreign nodes inside groups` |
| グループは子孫をすべて包む | `wraps groups around their (nested) members` |
| つながった行が水平に揃う | `keeps connected rows on one line` |
| サンプルの交差数が増えない | `stays within its crossing budget` |
| 自己ループの余白を保つ | `self-loop room` |

サンプルや `examples/` を追加したときは、`CROSSING_BUDGET` に上限を追加します。配置のルールを変えて交差数が減ったときは、上限も下げます。
