# 表現力の拡張: 採否と構文案

分岐シナリオとシーケンス図について、採否と理由、採用するものの構文案をまとめます。

| 機能 | 判断 | 理由 |
| :--- | :--- | :--- |
| 分岐シナリオ | 採用 | 正常系と障害系の比較は、ステップ再生が最も活きる用途。属性の追加だけで実現でき、`dav 1` の互換性を壊さない |
| シーケンス図（ライフライン形式） | 見送り | 別のレイアウトと描画が必要で、開発と保守の費用が大きい。現行形式の近似（`examples/05-sequence-payment-retry.dav`）で表現できる |

シーケンス図は、公開後にライフライン形式を求める要望が続いた場合に再検討します。

---

## 1. 分岐シナリオの構文案

`step` に省略可能な `scenario` 属性を追加します。

```dav
step "注文を受け付ける" { ... }
step "決済を実行する" { ... }

step "決済が完了する" [scenario: "正常系"] { ... }

step "カードが拒否される" [scenario: "障害系"] { ... }
step "在庫を戻す" [scenario: "障害系"] { ... }

step "結果を通知する" { ... }
```

文法の変更は `step` の属性ブロックだけです。

```ebnf
StepDecl ::= "step" String AttrBlock? "{" StepStmt* "}"
```

### 意味

- `scenario` のない `step` は、すべてのシナリオに共通する
- 1 つのシナリオは、共通の `step` とそのシナリオの `step` を、ファイルに書いた順に並べたもの。上の例の正常系は「受付、決済、完了、通知」、障害系は「受付、決済、拒否、在庫、通知」になる
- シナリオの順序は最初に現れた順で、先頭のシナリオを既定にする
- `state` の累積は、選択中のシナリオの `step` だけを対象にする
- `scenario` を 1 つも使わない図の動作は変わらない

### 決めた制約

- 1 つの `step` に指定できるシナリオは 1 つだけ。一部のシナリオだけで共有する `step` は、それぞれのシナリオに書く
- 入れ子の分岐は持たない。組み合わせは別の名前のシナリオとして書く
- シナリオ名は完全一致で比較する

### キーワードにしない理由

`branch { ... }` のようなブロック構文は、新しい予約語が必要です。予約語の追加は同じ名前の ID を使うファイルを壊すため、固定後の `dav 1` では行えません（[互換性方針](../03-specification/dsl-v1.md#6-互換性方針)）。`scenario` は属性名なので予約語になりません。

## 2. 表示

- シナリオがある図だけ、再生バーのステップ選択の隣にシナリオの選択を表示する
- ステップ番号と目盛りは、選択中のシナリオの中で数える
- シナリオを切り替えると、そのシナリオの先頭のステップに戻る
- 出力 HTML でも同じように切り替えられる

## 3. 実装の範囲

| 場所 | 内容 |
| :--- | :--- |
| `dsl/grammar`、`dsl/schema.ts`、`dsl/analyze.ts` | `step` の属性ブロックと `scenario` の検証 |

| `dsl/complete.ts` | `step` の属性の補完 |
| `editor/App.ts` | カーソルが別のシナリオの `step` に入ったときの切り替え |
| `prompt/`、`editor/docs/`、`docs/03-specification/dsl-v1.md` | 仕様と説明の更新 |
